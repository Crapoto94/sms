1 · Le principe : une passerelle, un téléphone

La passerelle est un serveur. Elle ne possède ni carte SIM ni antenne : elle ne sait pas émettre un SMS. Son rôle est de collecter les demandes d'envoi, de les mettre dans une file d'attente, puis de les confier à un téléphone Android équipé de l'application SmsGateway. C'est ce téléphone, avec sa carte SIM et son forfait, qui envoie réellement les SMS.

Point important : le serveur n'appelle jamais le téléphone. C'est toujours le téléphone qui appelle le serveur, à intervalle régulier (60 secondes par défaut). Le téléphone peut donc rester derrière une box, un pare-feu ou un réseau mobile, sans aucune ouverture de port.

Deuxième point important : la passerelle expose deux portes d'entrée distinctes, sur deux ports différents. Les agents se connectent avec un identifiant et un mot de passe sur la console web ; les applications tierces se connectent avec une clé API sur l'API publique. Ce sont deux serveurs séparés dans le même conteneur, qui ne partagent que la base.

  1. Dépôt par un agent. Un agent se connecte à la console web (port 3251) avec son identifiant et son mot de passe, puis écrit son message. Il est enregistré au statut en attente.
  2. Dépôt par une application. Une application tierce appelle l'API publique (port 3250) en présentant une clé « web ». Le message arrive dans la même file, avec son origine notée dans l'historique.
  3. Sondage. Le téléphone appelle l'API toutes les 60 secondes en présentant sa clé « passerelle ». Il en profite pour remonter ce qu'il a fait depuis le dernier appel.
  4. Attribution. Le serveur lui remet un lot de messages (25 au maximum par appel) et les passe au statut en cours d'envoi pour qu'aucun autre téléphone ne les reprenne.
  5. Émission. Le téléphone envoie les SMS par sa carte SIM, comme n'importe quel SMS classique. Les messages longs sont découpés puis réassemblés par l'opérateur.
  6. Compte rendu. Au sondage suivant, le téléphone renvoie les statuts (envoyé, remis, échec) ainsi que les SMS reçus sur sa ligne, qui apparaissent dans l'onglet Messages → Reçus.

Les deux portes, en pratique

Comme les deux services écoutent sur des ports différents, il vous faut soit deux URL (typiquement derrière un reverse proxy), soit une seule URL avec deux ports. Les deux fonctionnent ; le choix dépend de ce que vous voulez exposer à l'extérieur.

2 · Mettre un téléphone en service

L'application n'est pas publiée sur le Play Store : elle s'installe à partir de son fichier .apk. Android multiplie donc les avertissements, qu'il faut franchir un par un. Le téléphone doit ensuite devenir l'application SMS par défaut — c'est la condition posée par Android pour qu'une application puisse envoyer des SMS sans demander une confirmation à chaque message.

Choisissez un téléphone dédié, avec une ligne dédiée. Une fois l'application définie comme application SMS par défaut, tous les SMS reçus sur cette ligne remontent dans la console et l'application de messagerie habituelle ne reçoit plus rien.

  1. Autoriser les sources inconnues. Paramètres → Applications → Accès spécial → Installer des applications inconnues, puis autoriser l'application avec laquelle vous ouvrirez le fichier (le navigateur, ou le gestionnaire de fichiers). Sans cela, l'installation est bloquée sans explication.
  2. Télécharger l'APK. Le navigateur affiche « ce type de fichier peut endommager votre appareil » : choisissez Télécharger quand même. L'avertissement est générique, il s'applique à tout APK.
  3. Installer malgré Play Protect. À l'ouverture du fichier, Google Play Protect signale une « application non reconnue ». Choisissez Installer quand même (ou Plus de détails → Installer quand même). Si l'analyse est proposée, vous pouvez l'accepter puis installer.
  4. Accorder les autorisations. Au premier démarrage du service, l'application demande l'envoi de SMS, la réception de SMS et MMS, et les notifications. Toutes sont nécessaires : un refus empêche l'envoi automatique ou la remontée des SMS reçus.
  5. Définir l'application SMS par défaut. Bouton Définir comme app SMS par défaut, qui ouvre Paramètres → Applications par défaut → Application SMS. Choisissez Passerelle SMS. L'écran doit ensuite afficher « Statut : app SMS par défaut ✓ ».
  6. Saisir la première passerelle. Dans les paramètres de l'application : un nom libre, l'URL de l'API sous la forme http://192.168.1.10:3250 (le port de l'API, pas celui de la console), et la clé API créée dans l'onglet Clés API avec le type « Passerelle ». Puis Enregistrer.
  7. Ajouter d'autres passerelles. Le bouton + ajoute un profil. Répétez l'opération pour chaque passerelle à servir, avec à chaque fois l'URL de cette passerelle et une clé créée sur cette passerelle. Un même téléphone peut ainsi desservir plusieurs collectivités.
  8. Démarrer le service. Basculez l'interrupteur Service. Une notification permanente apparaît, et la ligne « Dernière connexion API » doit se mettre à jour dans la minute.
  9. Vérifier côté console. Dans l'onglet Passerelles, le téléphone apparaît avec son dernier contact et sa version d'APK, et la pastille en haut de page passe au vert.
  10. Envoyer un SMS de test. Le champ de test de l'application envoie un SMS réel à un numéro de votre choix : c'est la vérification de bout en bout la plus rapide.
  • Laisser le téléphone en état de servir. Branché en permanence, écran verrouillé mais appareil allumé, et l'optimisation de batterie désactivée pour l'application — sinon Android finit par suspendre le service.
  • Après un redémarrage. Le service repart tout seul au démarrage du téléphone et après une mise à jour de l'application ; il n'y a rien à relancer à la main.
  • Mettre à jour l'APK. Réinstallez simplement la nouvelle version par-dessus : les profils API, la clé et l'identifiant d'appareil sont conservés. La version installée remonte dans l'onglet Passerelles.
  • En HTTP ou en HTTPS. L'application accepte les deux. En dehors d'un réseau interne maîtrisé, utilisez HTTPS : la clé de passerelle circule à chaque sondage.

3 · Plusieurs téléphones pour une même passerelle

Un téléphone envoie un SMS toutes les quelques secondes : au-delà de quelques centaines de messages, il devient le goulot d'étranglement. Il suffit alors de déclarer une clé « passerelle » par téléphone et de les faire pointer vers le même serveur. Aucune configuration supplémentaire n'est nécessaire côté serveur : la répartition est automatique.

  • Répartition automatique. À chaque tour de 60 secondes, le serveur compte les téléphones actifs et n'accorde à chacun qu'environ 1/N des messages en attente. Le débit est donc multiplié par le nombre de téléphones.
  • Rattrapage. Si un message attend depuis plus d'un intervalle, il devient prenable par n'importe quel téléphone : une panne de terminal ne bloque jamais la file.
  • Reprise des blocages. Un message resté « en cours d'envoi » plus de 10 minutes (téléphone éteint, hors réseau) est automatiquement remis à disposition d'un autre téléphone.
  • Supervision. L'onglet Passerelles indique pour chaque téléphone son dernier contact, sa version d'APK et son compteur d'envois ; la pastille verte en haut de page compte les téléphones actifs.

4 · Plusieurs passerelles, plusieurs téléphones

Chaque entité (mairie, CCAS, police municipale…) peut disposer de sa propre passerelle, avec sa base, ses comptes et ses carnets. Mais les téléphones, eux, n'ont pas à être dédiés : l'application Android accepte plusieurs profils API. Un même téléphone interroge alors tour à tour chaque passerelle configurée et envoie les SMS des unes et des autres.

La relation est donc de plusieurs à plusieurs : une passerelle peut être servie par plusieurs téléphones, et un téléphone peut servir plusieurs passerelles.

  • Un profil = une passerelle. Dans l'application Android, chaque profil porte un libellé, l'URL de la passerelle (port API) et la clé « passerelle » créée sur cette passerelle. Les profils s'ajoutent et se retirent sans réinstaller l'APK.
  • Des clés distinctes. Le même téléphone reçoit une clé différente sur chaque passerelle. Révoquer la clé sur une passerelle ne coupe pas les autres.
  • Les passerelles s'ignorent. Elles ne communiquent pas entre elles pour les envois : chacune tient sa propre file, ses propres statuts, son propre journal. Seuls les carnets d'adresses peuvent être partagés (voir ci-dessous).
  • Une SIM, un forfait. Les SMS des différentes passerelles partagent la même ligne : c'est le point à surveiller lors du dimensionnement, pas la puissance du serveur.

5 · Synchronisation des carnets entre passerelles

Les carnets d'adresses sont souvent tenus à jour à un seul endroit (les élus, les agents d'astreinte, une liste de diffusion). L'onglet Synchro carnets permet à une passerelle d'aller recopier automatiquement des carnets hébergés sur une autre passerelle.

  • Sens unique. La passerelle qui synchronise tire les contacts depuis la source. La source n'est jamais modifiée et n'a rien à configurer, hormis fournir une clé « web ».
  • Mise en place. Onglet Synchro carnets → déclarer la source (libellé, URL sur le port API, clé « web » de l'autre instance) → parcourir ses carnets → cocher ceux à reprendre.
  • Rafraîchissement. Automatique toutes les heures, ou à la demande via le bouton de relance. Le contenu local du carnet synchronisé est remplacé à chaque passage : il ne se modifie pas à la main.
  • Visibilité. Les carnets synchronisés sont réservés aux administrateurs ; ils n'apparaissent pas dans l'interface d'envoi des groupes.
  • Réciprocité. Rien n'empêche A de synchroniser un carnet de B en parallèle : chaque passerelle choisit ce qu'elle importe.

6 · La vie d'un message

Chaque message porte un statut, visible dans l'onglet Messages et filtrable. Comprendre cet enchaînement suffit à diagnostiquer la quasi-totalité des situations.

7 · Qui fait quoi — les rôles

Deux mondes cohabitent : les comptes humains, qui se connectent avec un identifiant et un mot de passe sur la console (port web), et les clés API, qui authentifient des machines sur le port API. Les deux sont gérés depuis cette console.

Compte humain

Administrateur

Voit et gère l'intégralité de l'instance, tous groupes confondus. Seul rôle à accéder aux clés API, aux passerelles, aux journaux, aux comptes, aux groupes et à la synchronisation.

Compte humain

Utilisateur

Rattaché à un groupe. Il est redirigé vers l'interface d'envoi et ne voit que les carnets et les messages de son groupe. Il ne peut ni créer de compte, ni voir la configuration technique.

Attribut

Référent de groupe

Une case à cocher sur un compte utilisateur, qui désigne l'interlocuteur du groupe et le fait apparaître dans l'onglet Groupes. C'est une information d'annuaire : elle n'ouvre aucun droit supplémentaire.

Clé API

Clé « web »

Donne à une application tierce le droit de déposer des messages, de téléverser une pièce jointe et de lire les carnets, via l'API publique. C'est aussi la clé que présente une autre passerelle pour synchroniser des carnets.

Clé API

Clé « passerelle »

Réservée à un téléphone Android. Elle autorise uniquement le sondage de la file, la remontée des statuts et celle des SMS reçus. Elle ne permet pas de déposer un message.

Compte de secours

Compte admin intégré

Accessible en laissant l'identifiant vide sur l'écran de connexion. Son mot de passe est défini par la variable ADMIN_PASSWORD du docker-compose, et non depuis la console.

8 · Ce que peut faire un utilisateur

Un utilisateur travaille dans l'interface d'envoi, cloisonnée à son groupe. Il ne voit jamais les messages des autres groupes, ni la configuration technique de la passerelle.

Envoyer un message unitaire

  • Saisir un ou plusieurs numéros à la main, ou les piocher dans un carnet du groupe grâce à la recherche (nom, entité, numéro).
  • Rédiger jusqu'à 1000 caractères, avec palette d'émojis et compteur de segments SMS.
  • Joindre un fichier (10 Mo max) : la passerelle le transforme en lien de téléchargement ajouté au message, avec date d'expiration au choix.
  • Programmer l'envoi à une date et une heure futures, par pas de 5 minutes.

Envoyer à un carnet (campagne)

  • Choisir un carnet, cocher tout ou partie des contacts, et exclure au besoin les numéros présents dans un second carnet.
  • Personnaliser le texte avec les variables {prénom}, {nom}, {entité}, {service}, {direction}, {imei}, {puk}, {téléphone}.
  • Suivre la campagne comme un bloc : compteurs d'envoyés, remis, en vol et échecs, et annulation en masse tant que les messages n'ont pas été pris.

Tenir les carnets d'adresses du groupe

  • Créer, renommer et supprimer des carnets ; ajouter, modifier et supprimer des contacts.
  • Importer un fichier CSV avec correspondance des colonnes à l'écran et aperçu avant validation.
  • Renseigner les champs métier : entité, service, direction, IMEI, code PUK.
  • Blacklister un numéro : il est alors refusé à l'envoi, pour tout le monde et sur toute l'instance.

Vérifier une flotte de téléphones

  • Envoyer un message de test à un carnet et attendre la réponse des porteurs pendant 72 heures.
  • Suivre par contact l'état, la date de remise, la date de réponse, le délai et le texte de la réponse.
  • Exporter le résultat en CSV pour le rapprocher de l'inventaire (IMEI, PUK, service, direction).

Suivre ses envois

  • Consulter les messages du groupe, filtrer par statut, voir le motif d'échec et la passerelle utilisée.
  • Annuler un message encore en attente ou programmé.
  • Voir combien de fois un lien de pièce jointe a été ouvert, et depuis quel type d'appareil.

9 · Ce que peut faire un administrateur

L'administrateur dispose de tout ce qui précède, sans cloisonnement par groupe, plus la totalité de la configuration et de la supervision.

Piloter les accès

  • Créer des groupes, y rattacher les comptes, désigner les référents.
  • Créer des comptes, changer un mot de passe, désactiver ou supprimer un compte, et voir sa dernière connexion.
  • Émettre des clés API « web » ou « passerelle », avec durée de validité, puis les révoquer ou les supprimer. La valeur d'une clé n'est affichée qu'une seule fois, à sa création.

Superviser la flotte de passerelles

  • Voir chaque téléphone : dernier contact, identifiant d'appareil, version d'APK, messages en cours, envoyés, remis, en échec.
  • Consulter le journal des appels des passerelles (rapports remontés et messages récupérés à chaque tour).
  • Repérer les tentatives d'authentification échouées, avec IP et motif.

Voir l'ensemble du trafic

  • Tous les messages, tous groupes confondus, avec l'auteur et l'origine (console, interface d'envoi, API).
  • Tous les SMS reçus par les téléphones de la flotte.
  • Importer un lot d'envois en CSV, et exporter l'historique en CSV.

Gérer les données partagées

  • Accéder aux carnets de tous les groupes et en créer pour le compte d'un groupe.
  • Déclarer des passerelles distantes et choisir les carnets à synchroniser.
  • Tenir la liste noire des numéros, valable pour toute l'instance.

Tracer l'usage

  • Journal de la console : connexions, envois et campagnes, avec l'utilisateur, la quantité et l'adresse IP.
  • Documentation de l'API et description OpenAPI accessibles depuis le bouton Docs API.

11 · Glossaire

Passerelle
Selon le contexte : l'instance serveur complète (« la passerelle de la mairie »), ou un téléphone déclaré sur cette instance, tel qu'il apparaît dans l'onglet Passerelles.
Groupe
Unité de cloisonnement. Ses membres partagent les mêmes carnets et ne voient que les messages partis du groupe.
Carnet d'adresses
Liste de contacts appartenant à un groupe, avec les champs métier entité, service, direction, IMEI et PUK.
Campagne
Envoi groupé issu d'un carnet. Les messages restent regroupés dans l'historique, avec leurs compteurs et une annulation d'ensemble.
Variable
Marqueur du type {prénom} remplacé, pour chaque destinataire, par la valeur de sa fiche contact.
Liste noire
Numéros interdits d'envoi sur toute l'instance. Une campagne qui en contient est refusée avant tout départ.
Vérification de flotte
Campagne de test attendant une réponse des porteurs, pour contrôler qu'un parc de téléphones est bien en service.
Pièce jointe
Fichier téléversé sur la passerelle et diffusé sous forme de lien ajouté au SMS, avec date d'expiration et suivi des ouvertures.
Profil API
Couple URL + clé enregistré dans l'application Android. Un profil par passerelle servie.
Sondage
Appel périodique du téléphone vers le serveur. Il n'existe aucune connexion entrante vers le téléphone.
